Acrobat is desktop-focused and document-first. Adobe Express is web and mobile, and design-first. The ask was simple: when someone wants to edit an image in a PDF, send them to Express. Getting there meant designing across three layers at once — the technology, the process and the experience.

<Section eyebrow="Context" title="The ask was simple: send people to Express">
  <Figure narrow src="/images/edit-image/ei-d-handoff.webp" alt="Diagram: Acrobat (desktop focused, document-first) hands off to Adobe Express (web/mobile, design-first) to edit and stylize." caption="The plan: when someone wants to edit an image in a PDF, route them to Express." />
  <p><strong>Market context:</strong> Express had only just shipped a dedicated, Firefly-powered web and mobile experience in 2024, years after its 2021–22 rebrand. Canva, meanwhile, had turned its free plan into pandemic-era hypergrowth, reaching ~135M monthly users by 2023. Express needed distribution, fast — and Acrobat's install base was the fastest lever available.</p>
</Section>

</Section>

<Section eyebrow="#1 Tech layer" title="Understanding the use cases with user research">
  <p>Why might Acrobat users need to edit images in their PDFs? Acrobat users are diverse, and so are their image-editing use cases. The common theme: they're editing images in a PDF that</p>
  <ul>
    <li>they have shared for review,</li>
    <li>they're adapting from a previous document, or</li>
    <li>they received as a PDF and need to edit.</li>
  </ul>
  <Stats items={[
    { value: '400B+', label: 'PDFs opened per year' },
    { value: '16B', label: 'documents edited' },
    { value: '~20%', label: 'of documents contain an image' },
  ]} />
  <p>Qualitatively, we baselined how people used competitors to edit images before converting back to PDF.</p>
</Section>

<Section eyebrow="#1 Tech layer" title="Two products, two backends. One broken workflow.">
  <p>The real issue wasn't discoverability or polish — it was <strong>architectural</strong>. Every hand-off between Acrobat and Express was a chance to lose fidelity.</p>
  <Figure fit src="/images/edit-image/ei-d-backends.webp" alt="Diagram: Acrobat backend converts and re-imports to the Express backend; fidelity is lost here." />
  <p>How I navigate complex tech and workflow constraints: with a deep understanding of how it works, and of the use cases.</p>
</Section>

<Section eyebrow="#1 Tech layer" title="Bring Express to Acrobat, not Acrobat to Express">
  <Figure fit src="/images/edit-image/ei-d-sdk.webp" alt="Diagram: the Express backend delivers its tools into the Acrobat backend through an SDK. No hand-off, no conversion, no broken files." />
  <p><strong>The MVP:</strong> wrap Express's most valuable, most-used tools as an SDK, embedded directly inside Acrobat. No export. No re-import. No broken files.</p>
</Section>

  <Figure narrow src="/images/edit-image/ei-d-layers.webp" alt="Diagram: #1 Tech layer (done), with the Process/DACI layer and Experience layer still in progress. Aligning on the tech layer first bought the chance to move the design forward through process and experience complexities." />

<Section eyebrow="Discover" title="Entry point: Acrobat was already crowded">
  <p>Most people came to Acrobat only to view or sign a PDF. The first placement was buried under "Add image" and a right-click menu. <strong>Result:</strong> the tool existed, but almost nobody found it.</p>
  <Figure fit src="/images/edit-image/ei-entry-before.webp" alt="First placement: Edit image tucked into Acrobat's side panel, and in a long right-click menu." caption="Before: the side panel and the right-click menu" />
  <h3>People naturally select the image they want to edit</h3>
  <p><strong>Solution:</strong> I moved the entry point to the moment of image selection — contextual and in-flow. <strong>Result:</strong> it became the primary traffic source for the feature.</p>
  <Figure fit src="/images/edit-image/ei-entry-after.webp" alt="After: selecting an image in a PDF opens a contextual panel with Edit image at the top." caption="After: a contextual panel drives traffic" />
</Section>

<Section eyebrow="Edit" title="Challenge #1: Acrobat users don't know what to do with a brush 🖌️">
  <p>Remove object and Generative fill both relied on a brush to pick out an area first — not a familiar concept for non-designers.</p>
  <Points emoji="🔍" items={[
    'Generative fill is <strong>confusing</strong> to Acrobat users.',
    'Business professionals are <strong>not confident</strong> in their design skills.',
    'Acrobat users are <strong>not familiar with the concept of a brush</strong>.',
    '<strong>Writing prompts</strong> to visualize things is challenging for Acrobat users.',
  ]} />
  <Compare wide={false}
    before={{ src: '/images/edit-image/ei-brush-before.webp', alt: 'Before: a single Generative fill tool with brush size and a prompt field.' }}
    after={{ src: '/images/edit-image/ei-brush-after.webp', alt: 'After: a simpler Remove object tool with just a brush size and a Remove button.' }}
  />
  <p>What changed:</p>
  <ul>
    <li>Split one tool into two that better match use cases: <strong>Remove object</strong> and <strong>Insert object</strong>.</li>
    <li>Updated the copy to match users' expectations.</li>
    <li>Removed the prompt field from Remove object to reduce complexity.</li>
  </ul>
  <Figure fit src="/images/edit-image/ei-remove-object.webp" alt="The latest Remove object experience: Crop, Eraser, Remove and Insert in a contextual toolbar above the image." caption="Latest iteration: more contextual, easier to work with, and more generative results with credit usage in mind" />
</Section>

<Section eyebrow="Edit" title="Challenge #2: Reorder the image editing tools based on data">
  <p>The module went through three versions, each led by what the last one measured. Usage data optimized the tools' hierarchy for business professionals; user insights refined the interaction details.</p>
  <Figure fit src="/images/edit-image/ei-module.webp" alt="The edit image module powered by Adobe Express, with Generative fill, Remove background, Erase and Crop." />
  <Figure fit src="/images/edit-image/ei-module-versions.webp" alt="Versions 1, 2 and 3 of the edit image module side by side, with the tools reorganized in each." caption="V1 → V2 → V3, each improving rMAU and export rate" />
</Section>

<Section eyebrow="Apply" title="Challenge #3: A working AI tool isn't enough if it breaks the layout">
  <p>The missing piece of the end-to-end workflow was applying the image back to the PDF.</p>
  <h3>Crop should resize the canvas itself</h3>
  <p>After cropping an image in the edit image module, users expect the canvas to resize too — not leave ghost space when the image goes back into the PDF. <strong>Result:</strong> users can apply the resized image inside the PDF layout, with no extra canvas after cropping.</p>
  <Figure fit src="/images/edit-image/ei-crop-canvas.webp" alt="Left: a cropped image leaves unwanted negative space. Right: that negative space blocks image placement at the top of the page." />
</Section>
